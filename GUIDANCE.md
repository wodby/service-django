# Django on Wodby

What this service adds to the Python service it is based on. Check it before adding database, secret key or Celery settings to the project.

## Variables the service sets

| Variable | Meaning |
| --- | --- |
| `GUNICORN_APP` | `myapp.wsgi:application`. Change it on the service when the project package is not named `myapp`. |
| `CELERY_APP` | `myapp`. The Celery command line reads it to find the application. Change it together with `GUNICORN_APP`. |
| `DJANGO_SECRET_KEY` | A secret generated by Wodby for the service. It stays the same across deployments. |
| `DJANGO_DEBUG` | Set to `true` in environments of type `dev` only. Absent in every other type. |

Django does not read `DJANGO_SECRET_KEY` or `DJANGO_DEBUG` by itself. `settings.py` must take `SECRET_KEY` and `DEBUG` from them. Do not generate or commit another secret key.

## Linked services

In addition to the variables of the Python service:

| Link | Variable |
| --- | --- |
| Database | `DATABASE_URL`, the whole connection as one URL, with credentials |
| Redis or Valkey | `CELERY_BROKER_URL`, a `redis://` URL with the password, database `0` |

The service does not write Django settings. `settings.py` must build `DATABASES` from `DATABASE_URL` (or from the `DB_*` variables), the broker from `CELERY_BROKER_URL` and mail from `SMTP_HOST` and `SMTP_PORT`. Each variable is present only while its link exists, so the settings must work without it. Both URL variables hold a password: never print or commit their values.

## Celery worker

The optional `django-celery` service runs `celery worker --loglevel=INFO` instead of Gunicorn. It needs `celery` among the dependencies and a Celery application in the package named by `CELERY_APP`. The broker comes from the Redis or Valkey link, as `CELERY_BROKER_URL`.

## After every deployment

Wodby runs two commands for this service, in this order of declaration:

1. `python manage.py migrate`
2. `python manage.py collectstatic --no-input`

`manage.py` must be in the working directory, `/usr/src/app`, and `STATIC_ROOT` must be set for the second one. The start command and the pipeline do not have to run them. Nothing in the service serves the collected files: the application serves static files itself.

## Host checks

`ALLOWED_HOSTS` is the project's own setting. The environment's hosts are in `WODBY_HOSTS` (a JSON array), and the internal host name is in `WODBY_APP_SERVICE_NAME`.

## In a development workspace

Gunicorn runs with its polling reloader, so a saved Python file is picked up without a restart. A change to dependencies needs workspace preparation again. Migrations are not applied by file changes: run `manage.py migrate` with the workspace's Python.

## Check the result

- `python manage.py check` loads the settings with the container's environment.
- `python manage.py showmigrations` shows whether the database link works and which migrations are applied.
